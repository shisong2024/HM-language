## 1. 🔴 P0 健全性：SCC 不共享隐式约束（**最该先修**）

```text
def f x = g x;
def g x = if true then min x x else f x;
f 3;

--- 实际 ---
1: def f : Forall a0. (a0 -> a0)          <-- 完全没有约束！
2: def g : Forall a0. {Ord a0} => (a0 -> a0)
3: Type : Int
Eval Error:
1 | def f x = g x;
  |           ^
$implicit0 is an unbound variable.
```

**三个后果**：① `f` 的公开类型丢掉了约束 ⇒ 在**任意类型**上都能通过类型检查（健全性洞）；
② 运行期报内部名字 `$implicit0`（不该泄漏给用户）；
③ 明明两侧都该带 `{Ord a0}`。

**根因**（子代理定位到函数级）：`sccCheckerElab.checkOne`（`TypeCheck.hs:299-331`）
用 `recDicts`（318-319）+ `substRecCalls`（862-882）把字典参数**注入到组内其它成员的 body 里**，
但每个 binding 仍然只用**它自己**的 Wanted 列表去 `closeBinding`（322）。
⇒ 组内互相传的字典不在"我需要的约束"里，就被当成自由变量泛化掉了。

**同源更险的一例（变量捕获）**：

```text
def f x = let o = 0 in g x;
def g {o :: Ord a} x = if true then o.cmp x x else f x;
f 5;
--- 实际: Eval Error: Pattern match is not exhaustive: no arm matches 0.
```
调用方的 `let o = 0` **捕获了被注入的字典槽位**，整数 0 被当成 `Ord` 字典传了进去。

**修法方向**（与 `TODO/16` §6.1 一致）：SCC 内先合并所有成员的 Wanted、去重，
再按可达性分派给需要它的成员，最后才 `closeBinding`。

### 1.1 同族的另外两条（也是 P0/P1）

| 编号 | 现象 | 根因 |
|---|---|---|
| P0-3 | `def f x = let y = min x in y;` → `Cannot determine the type required by implicit parameter Ord a0.`（**该接受却拒绝**） | `inferLet`（`TypeCheck.hs:679-703`，691 行的 `closeBinding env1`）用的 env 里有**外层 def 的参数**，于是 `closeBinding` 的 `genVars`（807-821）把这个参数变量减掉了，约束既不能泛化也不能向外传 |
| P1-4 | `def f {o :: Ord a} x = let d = o in x;` → `Forall a0 a1. {Ord a0} => (a1 -> a1)`，且**永远调不动**（`a0` 在类型里根本不出现） | `inferDeclBody`（906-916）按**注解**造 Wanted，和实际用法无关；`closeBinding` 又把这个自由变量泛化进谓词 |
| P1-5 | `min;`（批顶层）报 `No implicit value of type Ord a0 is available.` —— 应该报 `Cannot determine the type required by ...` | `programChecker`（221-234，229 行）对**每个** Wanted 都直接 `resolveWanted`，绕过了 `closeBinding`/`typeChecker` 里那条 `isClosedType` 分类 |
| P2-8 | `def dup {o :: Ord Int} {o :: Ord String} x = o.cmp x x;` **静默接受**，第一个约束变成幽灵 | `inferDeclBody`（893-916）用 `M.insert` 覆盖，没有重名检查（仓库里 `fstDuplicate` 的先例没被用上） |

## 3. 🟠 P1 自定义操作符：fixity 预扫描是按行/按词做的（子代理 18/61 对抗项失败）

`scanFixities`/`symDef`/`decl`/`declOf`/`bare`（`Parser.hs:517-563`）——
**解析出来的 `StmtInfix` 从来不回填 `FixTab`**（`runProgWith` 只把预扫描的表传出去），
所以任何"扫描器没看见"的声明都是**纯空操作，却照样回显成生效**。

| # | 现象 | 期望 |
|---|---|---|
| 1a | `def <+> a b = a * 10 + b; infixl 1 <+>;` / `1 + 2 <+> 3;` → `Value: 24` | `33`（声明被忽略，用了默认 9） |
| 1b | `def <+> a b = a + b; infixl 12 <+>;` → **接受** | 拒：`single digit 0-9` |
| 1c | `def <+> a b = a + b; infixl 8 +;` / `1 + 2 * 3;` → `Value: 7` | 拒：`` `+` is a built-in operator`` |
| 1d | `infixl 1 <+>; def <+> a b = ...;`（同一行）→ **误拒** `expected \`infixl <0-9> <operator>;\`` | 接受，`33` |
| 1e | 同 `1a`，CRLF 换行 | 与 1a 一致（说明与行尾无关，是行内位置） |
| 1b(2) | `def ( <+> ) a b = ...`（括号内带空格）、`def<+> a b = ...`、`implicit def <+> a b = ...`、`def`⏎`<+> a b = ...` → 全都没有默认 fixity，每次使用都 Parse Error | 都该能定义（加一行显式声明就能用 ⇒ 定义本身合法） |

> `app/Main.hs:58` 把**每一行 REPL 输入**都过同一个 `runProgWith`，
> 所以 REPL 里 `def <+> a b = a + b; infixl 1 <+>;` 同样会丢 fixity。

### 3.1 内建操作符：三种行为互相矛盾

| 写法 | 实测 |
|---|---|
| `infixl 6 +;` | ❌ 拒：`` `+` is a built-in operator; its precedence is fixed.`` |
| `def (+) a b = 999;` 然后 `1 + 2;` | ✅ 接受；记号**仍走内建** ⇒ `Value: 3`（死代码） |
| `def (<) a b = true;` 然后 `1 < 2;` | ✅ 接受；记号**被抢走** ⇒ `Value: true` |
| `def ++ a b = 7;` 然后 `"a" ++ "b";` | ✅ 接受且**劫持内建** ⇒ `Value: 7`；`def ++ a b = a ++ b;` ⇒ `Recursion Limited` |

**机理**：`builtinOp`（`Parser.hs:34`）只在 fixity 声明的路径上被查，
`parseOpr` 又**先试 `opTable`**（254-258）⇒ `+ - * / ^ < <= == ...` 这些
`opTable` 里的名字永远走内建（`def` 成死代码），而 `++` 不在 `opTable` 里、
只靠 `builtinFix` 定优先级 ⇒ 它的**函数体**可以被 `def` 换掉。

**建议（最小且不改 `parseOpr`）**：`def` 一个与 `builtinOp` 重名的符号 → 声明处报错。
用户真正要的 `<+>` 这条路完全不受影响。

### 3.2 结合性检查

| # | 现象 | 说明 |
|---|---|---|
| 3 | `infix 6 <+>; infix 2 <%>;` / `1 <+> 2 <%> 3;` → **误拒** `non-associative` | `Parser.hs:264` 的比较**不看优先级**；把两个优先级对调就被接受（`-4`），所以只有"左边更紧"这一种顺序被误伤 |
| 4 | `infixr 6 <+>; infixl 6 <*>;` / `10 <+> 3 <*> 1;` → 静默取第一个算子的结合性（`6`） | 同级不同结合性本该报"cannot mix"；而同级 N/N **会**报（同一条检查里不自洽）。`TODO/15` §3 只把"N/N 不同名"记为已知取舍，这条是它的近亲 |

## 4. 🟠 P1 隐式参数的诊断

### F-4 `NoImplicit` 没有位置，也没有上下文注记

```
data Foo = Foo;
def use {o :: Ord Foo} x = o.cmp x x;
use Foo;

2: Type Error:
No implicit value of type Ord Foo is available.        <-- 没 caret、没说在哪个 def
```

对照同一次运行里 `Unknown type: Nothing2.` **有** `in definition of \`use\`` 注记。
根因：`inferDeclBody:916` 造 Wanted 时 `wtdSpan = Nothing`；`resolveWanted`
（`:769`）用 `Located (wtdSpan wtd)`。**实参位置**的缺字典（`useB (Box 1)`）反倒有 caret。

### F-6 `ImpCandidateHasContext` 的文案指错对象

`Forall a0. Ord [a0]` 里**没有 `=>`**，却被描述成 "still requires ..."。
真正的理由是"候选不是闭类型"。`Located Nothing` ⇒ 也没有 caret。

### F-7 已确认、**必须写进文档**的三条语义

1. **参数"用了才存在"**：`def a {o :: Ord a} = o;` ⇒ `Forall a0. {Ord a0} => Ord a0`（对）；
   而 `def a2 {o :: Ord a} = Ord { cmp = lambda x y -> EQ } :: Ord [a];`
   ⇒ `Forall a0. Ord [a0]`（`o` 没被用上，**参数静默蒸发**、约束也消失）。
2. **注解的类型变量与参数的类型变量是分开的**（子代理用"惰性使用"复现：
   `def a2b {o :: Ord a} x = (o, x, Ord {...} :: Ord [a]);`
   ⇒ `Forall a0 a1 a2. {Ord a0} => (a1 -> (Ord a0, a1, Ord [a2]))`）——
   所以 head 与参数相关的实例（`Ord [a]` from `Ord a`）现在**写不出来**。
3. **包装式实例天然自引用**：⇒ `Forall a0. {Ord [a0]} => Ord [a0]`（已进 spec 作 PIN）。

### 新发现（子代理，P2）

- **会话把已提交的候选压平成一帧**：模块里 `implicit def myInt :: Ord Int` 提交后

### BUG 2（HIGH）：全局字段表跨模块**静默偷字段**

键是**裸字段名**，`recProgram.agrees` 只比 `base fiCtor`（最后一个 `.` 之后的文本）+ 序号 + 元数，
`aliasFields` 只给**胜出者**加前缀。三种表现：

| 面 | 复现 | 实际 |
|---|---|---|
| a | 两个模块各有 `data C = C { x :: … }`（类型不同、形状同） | 后导入的赢，先导入那侧的 `.x` 变成 `expected A.C but got B.C`（**依赖导入顺序、无诊断**） |
| b | REPL 里先 `data C = C { x :: Int };` 再 `import <形状不同的 data C> as A;` | 导入**不报错**，本地记录被毁：`(C { x = 2 }).x;` ⇒ `` `C` is not a record constructor.``。因为 `addDecl` 的 `dropData (dName d)` 用的是**未限定**的 data 名（`Parser.hs:660-663`），在 `agrees` 能拒绝之前就把本地条目丢了 |
| c | 一个**类型检查失败**的模块仍然安装了字段表（`Main.hs:283-284` 在 `execBatch` 之前就设了 `sFields`） | `(A.mkA 1).x;` ⇒ `Unknown constructor: X.C.` |

### BUG 3（HIGH）：操作符/fixity 是全局的，**且 `unload` 清不掉**

- **重载后残留**：模块里删掉 `def (<+>)` 与 `infixl`，重新 `:load` 之后 `1 <+> 2` **仍然**求值成功
  （fixity 也漏了，所以连 Parse Error 都没有）。`Main.unload` 的 `strip` 只删 `<Alias>.` 前缀键，
  而操作符按设计就是不加前缀的（`Parser.topsOf` 用 `isOpName` 排掉、`Qualify.hs:37` 不动 `StmtInfix`）。
- **导入顺序改变解析**：两个模块各定义 `<+>`（优先级 6 / 7），
  `import oa; import ob; 1 <+> 2 * 3;` ⇒ `6`，反过来 ⇒ `7`。同一表达式、无诊断。

### BUG 4（MEDIUM）：`implicit def (<+>) …` 拿不到默认 fixity

```text
implicit def (<+>) a b = a + b;
1 <+> 2;        ⇒ Parse Error: unexpected '<'
```
`scanFixities.symDef` 只特判 `def`（`Parser.hs:534-539`）。**已复现确认。**

### BUG 5（MEDIUM）：**失败的批/导入仍然发布声明**

同一行 `type T = Int; def bad = 1 + true;` 失败之后：`1 :: T;` 仍然工作（同义词泄漏，
`Main.hs:70-73` 在检查之前就设了 `sSyns`）；`data C …; def bad = …` 之后字段泄漏
（报 `Unknown constructor: C.` 而不是 `unknown field`）；fixity 泄漏（`1 <+> 2` 能解析、
死在 `<+> is an unbound variable`）；失败的 `import` 仍然占住了别名。

### BUG 6（MEDIUM）：类型同义词可以和 data 同名，并**在所有类型位置遮蔽它**

```text
type Pair = Int;
data Pair = Pair Int;
(Pair 1) :: Pair;    ⇒ Type mismatch: expected Int but got Pair
```
`type Maybe = Int;` 还能劫持 prelude 的 `Maybe`。`checkDataDecls` 只查 data-vs-data 与 ctor-vs-ctor。

### BUG 7（MEDIUM）：导入解析**只认 `/`**，可能静默加载无关文件

`dirOf` 用 `T.breakOnEnd "/"`（`Main.hs:241-242`）⇒ Windows 反斜杠路径的目录算成 `.`，
相对 CWD 解析。所以 `& v1.exe build-tmp\drv.txt` 里 `import px_sib.txt` 会报读不到；
**更糟**的是 `import test.txt as T;` 会静默加载**仓库根**的 `test.txt` 并执行它。

### BUG 8（MED-LOW）：穷尽性检查**假阴性**

```text
data L = A | B;
data T = C L Bool;
def f t = match t with C A true -> 1 | C B false -> 2;   ⇒ 通过类型检查
f (C A false);   ⇒ Eval Error: Pattern match is not exhaustive
```
`TypeCheck.exhaustive` 的 `covered` 把**各参数列独立**检查（`:594-607`），
而不是取行集合的笛卡尔积。**不是记录特有**（位置式语法一样），记录只是更容易撞上。

### 明确**不算 bug**（子代理已钉成 `[info]` 检查）

- 含闭包的 record/list 上 `==` 是运行期 `not comparable`（`eqV` 没有 `VClosure` 分支）——
  与裸闭包 `f == g` 一致，无语义上的 `Eq`。
- 字段名全局唯一**且包括 prelude**：`data Foo = Foo { cmp :: Int };` ⇒
  `` field `cmp` is already a field of `Ord` `` ⇒ `cmp` 这个字段名永久不可用。
- 隐式候选按**精确类型**在**一帧**里匹配：导入一个 `Ord Int` 候选会让 `min 1 2`
  与 prelude 的 `ordInt` 歧义；模块**永远无法遮蔽** prelude 的候选。
- 可失败的 `let`、行尾 `--` 都是**按设计**拒绝；`import` 行在被导入文件的 body 之前处理。
- 小疣：`Pretty.hs:226` 打的是 "Not evaluared"（拼写错），而且**现在可见**——
  因为 BUG 1 正好把用户带到这条路径上。

### 攻击过但**站得住**的接缝（可当回归守卫）

记录字段类型里的同义词、构造子参数里的同义词、操作符 body 注记里的同义词、
match 被scrutinee 注记里的同义词、隐式候选注记里的同义词、同义词的同义词、跨模块同义词 + 限定操作符；
跨模块记录（构造/更新/模式/链式访问/`:t`）；字符串里含 `{ } : ; -- , =` 与 `\"`（字段值与字段模式两种位置）；
`\uXXXX` 含 `\u000A` 进记录字段；多行记录声明/字面量里的整行 `--` 注释；
元组解构 `let`；别名重载对值/类型/构造子/**字段**/同义词/隐式候选都干净（**只有操作符漏**，即 BUG 3）。

> **方法说明**：普通 PowerShell 管道会一次性缓冲 stdin，所以重载类检查（BUG 3a、5）
> 是用 .NET `Process` + 显式 flush 的 stdin 驱动**真正的交互式会话**（`probe-x.ps1` 的 `Ask-Px`）——
> 这才让"改模块文件、在同一会话里重新 `:load`"可观测。
